\subsection{Surface-informed polymer layer}
\label{sec:surfaceInformedPolymerLayer}

This verification folder exercises the surface-informed polymer as both a continuum material and a finite-thickness cohesive-zone material.  Four variants are run from one input: continuum tension, continuum compression, cohesive-zone tension, and cohesive-zone compression.  The continuum variants place a continuum polymer layer between stiff elastic loading bars and tie the two bar/polymer interfaces with stiff linear elastic cohesive zones.  Those tie zones are not polymer material models; they are numerical bonded-interface fixtures that transmit load without relying on mixed continuum cells at the bar/polymer material interfaces.  The cohesive-zone variants retain two stiff elastic blocks separated by a finite-thickness polymer cohesive interface with the same film thickness.  The imposed cosine ramp is intentionally slow compared with the layer acoustic-transit time so the history is a quasi-static constitutive check rather than a wave-propagation benchmark.

The comparison curves use the continuum J2 radial-return update with retained mean stress for continuum variants and the reduced cohesive thin-film update with the same retained volumetric normal stress for cohesive-zone variants.  In the cohesive projection, the mean film stress $p=K\epsilon_n$ is retained and only the deviatoric normal and shear stresses are returned to the scalar flow surface.  The verification uses reusable non-polymer \texttt{ElasticIsotropic} block and \texttt{UncoupledCohesiveZone} tie cards from \texttt{pfw\_materials.py}; the polymer response is carried by the continuum polymer layer in the continuum variants and by the polymer cohesive law in the cohesive-zone variants.  The benchmark explicitly initializes the particle and cohesive-zone temperature to 300 K using the particle file and a constant \texttt{TemperatureProfile} event, so the response is not left at the material reference temperature by default.  The input explicitly requests \texttt{particleStress}, \texttt{particleDamage}, and \texttt{particlePlasticStrain} through \texttt{plottableFields}.  The equivalent-plastic-strain visualization uses the stored constitutive \texttt{equivalentPlasticStrain} field when available and can fall back to a VisIt/post-processing expression computed from the primitive plastic-strain tensor components.  For measured histories, the film-strain coordinate is reconstructed from the actual deformation-gradient or length history written by GEOS when available, with the input cosine loading table used only as a fallback.  When VisIt is available, it also renders loading-direction stress and equivalent plastic strain at four output states for each variant.
